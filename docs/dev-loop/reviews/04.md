## 案

### 4. ホストの reset とテール

- 承認されて入れた（ユーザーの言葉: 「reset とテールに、入れない案を合わせる」）。テールは設定から求める案。
- いまは `reset()` が無く、`getTailLengthSeconds()` は 0（`LessonProcessor.h`）。JUCE の VST3 の殻は `setProcessing(false)` で `reset()` を呼ぶので、ホストが止めても状態が残る。
- 測った値（48 kHz、Auto Gain は切）:

  | 状態 | いま | 案 |
  | --- | --- | --- |
  | コンプ（−20 dB、4:1、Attack 10 ms）に 0 dBFS のノイズを 1 秒、止めて次の再生の頭の GR | 15.0 dB。1 dB を切るまで Release 100 ms で 0.291 秒、1000 ms で 2.728 秒 | 0 dB |
  | EQ（ベル 20 Hz・Q 12・+18 dB）に 20 Hz の正弦を 2 秒、止めて次の再生の無音の頭 512 サンプル | +16.2 dBFS の鳴り残り | ちょうど 0 |

- 案の中身（`reset-and-tail.patch`）:
  - core: `Compressor::reset`、`EqLoudness::restart`、`EqEngine::reset`・`CompEngine::reset`。どれも確保しない（noexcept）。`prepare` は「確保してから reset」にしたので、ゴールデンはビット単位のまま。
  - プラグイン: `EqProcessor::reset`・`CompProcessor::reset` がエンジンを今の設定で reset し、取り出し口を空にする。SDK の決まりで `setProcessing` は UI か処理のスレッドで呼ばれ、`process` とは重ならない。
  - EQ のテールは設定から求める（`eqTailSeconds`）。段ごとに、いちばん遅い極が 120 dB とその段の最大の利得のぶん下がる時間に 1.25 を掛け、全段で足す。コンプのテールは 0 のまま（GR が戻るのは鳴り残りではない）。
  - 1.25 の理由: Blink はビクアッドの出力を毎サンプル float に丸めて帰還させるので、1 に近い極は遅くなる。ベル 20 Hz・Q 12・+18 dB は係数では 16.1 dB/s、192 kHz で回すと 15.0 dB/s（44.1〜96 kHz では 16.1）。その差（実測が式の 1.057 倍）の上に余裕をとった暫定の値。
- テールの式と実測（0 dBFS の正弦を 2 秒入れて止めてから −120 dBFS を切るまで）:

  | 設定 | 式（44.1・48 kHz） | 実測（44.1・48 kHz） | 式（192 kHz） | 実測（192 kHz） |
  | --- | --- | --- | --- | --- |
  | ベル 20 Hz・Q 12・+18 dB | 10.69 秒 | 8.46 秒 | 10.69 秒 | 9.04 秒 |
  | ベル 1 kHz・Q 12・+18 dB | 0.21 秒 | 0.17 秒 | 0.21 秒 | 0.17 秒 |
  | HP 20 Hz・48 dB/oct | 1.30 秒 | 0.57 秒 | 1.30 秒 | 0.57 秒 |
  | 7 つのバンドを 20 Hz に重ねて +18 dB | 35.2 秒 | 14.7 秒 | 35.2 秒 | 15.8 秒 |
  | HP 30 Hz、ベル 2 つ、HS +3 dB | 0.36 秒 | 0.19 秒 | 0.36 秒 | 0.19 秒 |
  | 既定 | 0 | — | 0 | — |

  乱数の設定 240 通り（44.1・48・192 kHz）で、実測が式を超えたのは 0 回（実測は最大で式の 0.83 倍）。
- 決めてほしいこと: VST3 にはテールが変わったことをホストに知らせる仕組みが無い（`restartComponent` の旗に無い）。ホストが起動のときに 1 回だけ読むと、既定（0）のまま覚えて、あとで極端な設定にしても反映されない。代わりの案は固定の最悪値（16 秒ほど）で、切られることはないが、テールを守るホストでは書き出しやフリーズのたびに 16 秒の無音が足される。推奨は設定から求める案。
- 確かめたこと: worktree の Release で ctest 77 件（足した試験: `core_tests "[reset]"` 3 件、`plugin_tests` の `[bus]` 2 件、`rt_alloc_test` は 500 ブロックごとに reset も数える）、validator `-e` 537 件 ×2、pluginval strictness 10 ×2 が合格。`[bus]` の reset の試験は、reset の中身を外すと落ちる。

### 5. コンプの検出の上限

- 承認されて、数でないサンプルを検出に入れない案を入れた（ユーザーの言葉: 「reset とテールに、入れない案を合わせる」）。上限の案は入れていない。
- いまは Inf を float の最大として読むので、1 サンプルの Inf で検出のレベルが約 770 dB になる（`Compressor.cpp` の `gainFor`）。NaN は `a > peak` が偽なので、もともと検出に入らない。
- 無音の中に 1 サンプル入れたときの GR（48 kHz、Threshold −20 dB、Attack 10 ms。最後の行だけ Threshold −60 dB、Attack 0.1 ms）:

  | Ratio・Release | 入れたサンプル | 最大の GR | GR が 40 dB 以上の時間 | 1 dB を切るまで | 0.1 dB を切るまで |
  | --- | --- | --- | --- | --- | --- |
  | 4:1・100 ms | Inf（いま） | 520.4 dB | 0.277 秒 | 0.646 秒 | 0.877 秒 |
  | 4:1・100 ms | 上限 +24 dBFS | 29.0 dB | 0 | 0.358 秒 | 0.588 秒 |
  | 4:1・100 ms | 上限 0 dBFS | 13.2 dB | 0 | 0.279 秒 | 0.509 秒 |
  | 4:1・1000 ms | Inf（いま） | 520.4 dB | 2.586 秒 | 6.276 秒 | 8.578 秒 |
  | 4:1・1000 ms | 上限 +24 dBFS | 29.0 dB | 0 | 3.387 秒 | 5.689 秒 |
  | 4:1・1000 ms | 上限 0 dBFS | 13.2 dB | 0 | 2.598 秒 | 4.901 秒 |
  | ∞:1・100 ms | Inf（いま） | 693.8 dB | 0.306 秒 | 0.675 秒 | 0.905 秒 |
  | ∞:1・100 ms | 上限 +24 dBFS | 38.6 dB | 0 | 0.386 秒 | 0.617 秒 |
  | ∞:1・1000 ms | Inf（いま） | 693.8 dB | 2.874 秒 | 6.563 秒 | 8.866 秒 |
  | ∞:1・1000 ms | 上限 +24 dBFS | 38.6 dB | 0 | 3.675 秒 | 5.977 秒 |
  | ∞:1・1000 ms（−60 dB、0.1 ms） | Inf（いま） | 830.6 dB | 3.054 秒 | 6.743 秒 | 9.046 秒 |
  | ∞:1・1000 ms（−60 dB、0.1 ms） | 上限 +24 dBFS | 84.0 dB | 0.763 秒 | 4.452 秒 | 6.754 秒 |

  上限 +40・+6 dBFS も測った。4:1・100 ms で最大の GR はそれぞれ 39.5・17.1 dB、1 dB を切るまで 0.389・0.305 秒。
- 推奨は上限ではなく、数でないサンプルを検出に入れない案（`comp-detector-ignore.patch`）。悪いサンプルは 0 として扱われ（ステレオならもう片方のチャンネルの大きさ）、GR は付かず、戻る時間も 0。有限の入力では値が変わらないので、Web アプリとビット単位で同じまま。画面の音量の流れの点にも Inf が届かなくなる（いまは届く）。
- 上限の案（`comp-detector-cap.patch`、+24 dBFS）は、有限でも +24 dBFS を超えるピークの GR が変わる。画面の点には Inf が届いたまま。
- 確かめたこと: 推奨の案で `core_tests` 73 件が合格（ゴールデンはビット単位のまま）。足した試験 `[nonfinite] the compressor's detector does not hear an Inf or a NaN`（悪いサンプルを入れた出力・GR・画面の点が、0 を入れたものとビット単位で同じ）は、いまのコードでは落ちる。
